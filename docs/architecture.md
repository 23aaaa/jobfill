# 架构与扩展边界

## 核心决定

用同一套领域模型驱动资料维护页、侧栏和 Excel，而不是为三个入口维护三份字段映射。求职者自由增删结构；招聘网站只收到用户明确点击的一个值。整个资料库从不注入招聘页面。

```
资料维护页 / 原生侧栏 / 独立 HTML
                │
     UI 状态、渐进展示、明确确认
                │
    领域模型 + 模板目录 + 严格校验
          ┌─────┴────────┐
    Repository        Import / Export
 chrome.storage.local  XLSX / JSON / AES-GCM
 localStorage+锁        有界 ZIP + XML
          │
 Service Worker（受信任消息、修订串行化）
          │ 仅 {token, value}，绑定 tab/document
 内容脚本（隔离世界）→ DOM adapter → 网页一个控件
```

## 分层

| 路径 | 责任 | 不应承担的责任 |
|---|---|---|
| `domain/model.js` | 统一结构、限制、稳定 ID、搜索/复制/统计、验证 | Chrome API、DOM、文件读写 |
| `domain/templates.js` | 可选默认模块、字段分组、初始敏感标记 | 网站定位器、永久锁死的必填字段 |
| `infra/storage-core.js` | 保存语义、修订冲突、历史与删除代际 | 页面交互、具体存储 SDK |
| `infra/repository.js` | 扩展消息仓库 / 独立页本地仓库 | 把全部资料暴露给内容脚本 |
| `infra/zip.js`, `xlsx.js`, `vault.js` | 有界解析、双向文件、加密备份 | 任意 Excel 兼容、AI 猜测、修改原文 |
| `ui/dom.js`, `style.css` | 安全 DOM 组件、对话框、可访问性、布局 | 持久化和招聘网站操作 |
| `ui/app.js` | 资料编辑、导航、导入确认、侧栏使用流程 | 直接访问招聘网站 DOM |
| `background.js` | 受信任来源校验、串行保存、临时授权、目标路由 | 注入整个资料库、永久监听全网 |
| `bridge/content.js`, `fill-engine.js` | 目标发现、单值写入、事件分发、验证与撤回 | 本地资料库读取、页面提交、云端调用 |

没有引入服务端或 AI 服务。当前项目规模下保持 ES Modules 与 JSDoc，而非为了“架构感”建立多服务或引入大型框架。构建器只处理本项目静态命名导入；不要把它当作通用 JS 打包器。

## 数据模型

`Profile → Module[] → Entry[] → Field[]`；字段的 `group` 构成可折叠分组。分组是名称维度，不额外增加难以在 Excel 中维护的实体。模块、条目与字段 ID 不受改名影响。

`version` 是文件结构版本；`revision` 是一次保存后的乐观并发版本，不能互相替代。仓库的 `epoch` 是删除/重置代际，阻止其他窗口的旧草稿在清空后把资料写回来。导入内容的 revision 不是服务端权威；保存时由仓库递增。

所有 `value` 为原始字符串。日期、年月、电话、证件号和数字文本不做类型强制转换。真正写入 HTML 控件时，浏览器可能把 CRLF/CR 规范为 LF；这不是对资料库原文的改写。普通单行控件若会截断或改变格式则拒绝填写。

字段支持 `text / multiline / date / month / email / tel / url / number` 八种提示类型；不允许用户输入任意脚本型组件。任意模块和字段名称是数据，而非执行代码。

## 状态与错误

550ms 防抖保存，Ctrl/Cmd+S 可显式触发。保存失败不显示成功，保留草稿并允许导出。受信任扩展页面通过 service worker 单写队列保存；独立 HTML 通过 Web Locks 协调同源页面。实际 Chrome 锁/持久化与跨窗事件仍需原生验证。

结构调整、删除和导入前保留本地检查点，最多三份且受总字节预算约束，不是每次击键的无限版本控制。最大资料 2MiB、导入文件 8MiB、60 模块、600 条目、6000 字段、单字段 32767 UTF-16 单元。达到限制时明确失败，不默默丢数据。历史空间不足会丢弃最旧历史，不丢弃当前资料。

## 填表信任边界

1. 用户通过浏览器工具栏动作授予当前页 `activeTab`；打开原生侧栏，并把内容脚本注入该页。
2. 内容脚本以 composedPath 识别原生控件/开放 Shadow DOM，只报告控件标签、类型与随机 token。
3. 后台从 Chrome 的 sender 得到 tab、frame、document 和 origin，不相信请求自报的网站来源。
4. 侧栏传递一个值。后台核验当前活动 tab、token 和 documentId，精确路由给原文档。
5. DOM adapter 检查目标仍存在、仍可编辑且焦点匹配；执行原生 setter，发出 beforeinput/input/change，并检查 160ms 后值是否保留。
6. 只保存最近一次写入的局部撤回信息。已有后续用户修改时拒绝撤回，不自动提交。

“160ms 后值保留”不代表网站服务端已保存；用户必须自行核对网站最终结果。复杂控件、跨域框架、网站拦截、权限撤销均是显式失败/手动兜底路径。

## Excel 协议

新版一分类一张表，A:C 为可见内容，D:H 为隐藏关联信息，末尾隐藏结构表。`infra/workbook-v2.js` 负责用户可读协议和纯函数转换；`infra/xlsx.js` 保留有界 XML 解析与旧版格式读取。可见内容优先，不在隐藏区重复保存字段值。改名、复制段落、自定义字段、工作表复制和空结构均有回归测试。详见 `excel-format.md`。

## UI 设计系统与搜索

`shared/design-tokens.js` 是没有 DOM 依赖的配色 token，UI 与 Excel 共用。`ui/theme.js` 负责白名单偏好、存储失败降级和根元素变量，偏好不是简历数据，不修改资料修订。样式由 CSS 一套规则管理，维护页/侧栏只做视图差异。

搜索是领域层的只读规范化索引，支持 NFKC、大小写和多词同时匹配，排除敏感值。UI 只保留一个应用级入口，70ms 防抖并避开输入法组合期。全量匹配后分批呈现，不把前 200 项当作全部。折叠记录按需挂载组件，避免数据量增加时预创建大量无用输入框。

## 后续增加能力的位置

新增预设模块只改 `templates.js`；用户自定义不需代码修改。新增网站专用适配器应放到 `bridge/adapters/`（当前没有这个实现目录），通过明确的识别/写入/校验/撤回接口注册，配对应站点测试，不在 UI 中硬编码选择器。新增数据结构版本应增加显式迁移器与往返回归测试，不能静默解释未知版本。未来接入云同步/支付会引入新数据、权限与隐私边界，需要单独设计，当前不是隐含存在的功能。
