# Excel 格式与兼容

## 给使用者的格式

底部工作表是分类，合并的标题行是一段经历，普通行是项目。只需看三列：分组、项目、填写内容。首次使用不要求接触程序编号。内容列是文本格式；改名、新增项目、复制整段和复制工作表都可以导回。

填写提示放在最后的「填写帮助」工作表，而不是让第一屏变成教程。首张工作表是基本信息。分类表冻结首行、隐藏网格线、长文换行、内容列浅色。长标签和多行值共同参与行高估算；超长单元格行高上限 180pt，完整内容仍可在编辑栏读取。

空白模板包含 20 类、230 项，但用户不必填全；应用默认只启用 8 类常用资料。低频和敏感项目按需提供。

## 开发者协议

领域 `Profile.version` 仍为 1。Excel 自身升级为 `Xiaoshidi workbook 2`，与资料版本、存储修订号不同。

每个分类表 A:C 是可见内容。D:H 隐藏列依次为记录种类、记录 ID、字段 ID、提示类型、敏感标记。记录行 D=entry，字段行 D=field。隐藏的 `_小师弟结构` 保存资料元数据与 sheetId 到分类的映射，**不保存另一份字段值**，可见单元格永远是字段内容的依据。

原分类名称超过 Excel 31 字符或含工作表保留字符时只适配工作表显示名，原名仍能往返。用户真正修改工作表标签时采用新名称。同名冲突做安全后缀处理，不截断半个 Unicode 代理对。

复制整段 / 字段时，重复的行级身份会创建独立的新身份；复制工作表由新 sheetId 识别为新分类。新插入项目行无需填写隐藏列，继承上方分组，新出现的证件类标签默认标记敏感。原有明确敏感标记仍按原值保存。

导入先构建独立候选资料，全部校验通过后才显示预览；确认前不修改当前资料。表头缺失、未知额外内容列、空项目名、错位的记录归属、无效类型 / 标记、公式 / 数字单元格均拒绝，不静默丢弃。

## 旧版兼容

旧版 `ApplyDock workbook 1`、`资料表` / `_投递舱` 表名、`applydock.profile.v1` 存储键、`.applyvault` 魔数与认证附加数据保持兼容。这些是内部协议，不是遗漏的用户界面改名。JSON 字段名和结构不做翻译。

新版导出只生成新版 Excel；仍能读旧版格式。旧版客户端不能读新版工作簿。升级前先保留旧备份。

## 安全与格式限制

值是字符串；导出以显式字符串写入，`=...`、前导零、CRLF 和 `_xNNNN_` 字面量不得变成公式或转义损坏。导入不会执行公式、宏、外部链接或 DTD/ENTITY。ZIP 的路径、数量、压缩方式、CRC 与解压尺寸仍受原有上限约束。

已经变成数值并被 Excel 舍入的长证件号不可恢复，错误提示要求重新输入原始文本，而不只改显示格式。

## 实际验证范围

单元测试覆盖可见值编辑、分类和字段更名、空结构、复制行/段/表、删除、重排、自定义字段、特殊字符和拒绝路径。浏览器测试覆盖真正的产品导出、XML 解析和 UI 导入预览。

测试夹具 `independent-template.xlsx` 是通过 artifact_tool 独立加载、编辑样式、再保存的压缩工作簿，用来验证独立写入器的兼容性。该工具的再保存会丢失工作表隐藏状态和冻结窗格，故它**只作为兼容测试夹具，不作为给用户的模板**。对外交付模板由产品实际导出器生成，并检查隐藏状态、冻结、文本格式与渲染。

尚未实际操作 Microsoft Excel / WPS 的桌面 UI 做编辑再保存。XML 变更测试和独立写入器测试不能代替这一步，详见发布检查清单。
